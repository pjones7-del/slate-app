# Slate for iPhone

The football board as an iPhone app, delivered through TestFlight. The app is a native shell around the same board the home-screen
web app shows (`Board.url` in `Slate/Board.swift`), so a change to the board reaches the app the moment it's pushed; only changes
to the app itself need a new build. Version 0.1 is the board, its icon and launch screen, links out in an in-app Safari sheet,
Print, and a retry screen; lock-screen live scores come next.

## How it builds

`.github/workflows/ios.yml` runs on GitHub's Macs (`macos-26`, newest Xcode; App Store Connect takes only builds made with the
iOS 26 SDK or later). Every push to `main`, and the Run workflow button, compiles the app for the simulator, which needs no Apple
account. When the Apple values below are set, the same run archives the app, signs it with Apple's cloud-managed distribution
certificate, and uploads it to App Store Connect, where it shows up in TestFlight after Apple processes it (usually minutes).
The build number is the workflow's run number; the version is `MARKETING_VERSION` in `project.yml`.

The project file is generated by XcodeGen from `project.yml` on the build machine; it isn't kept in the repo.

## One-time Apple setup (after the Apple Developer Program enrollment is approved)

1. Register the app ID: developer.apple.com, Certificates, Identifiers & Profiles, Identifiers, +, App IDs, App, description
   "Slate", explicit bundle ID `io.github.pjones7-del.slate`. (Done 11/3/2026.)
2. Create the app in App Store Connect: Apps, +, New App, iOS, a name, the bundle ID above, any SKU. (Done 11/3/2026: "SLATE
   Scoreboard", SKU slate-ios, Apple ID 6830267713. The App Store name must be unique and plain "SLATE" is taken; it shows
   only in TestFlight until a public release. The label under the icon is `CFBundleDisplayName` in `project.yml`: SLATE.)
3. Create an API key: App Store Connect, Users and Access, Integrations, App Store Connect API (Request Access the first
   time), Team Keys, +, role Admin (cloud signing needs it). Download the .p8 file (Apple offers it once), and note the Key ID
   and the Issuer ID.
4. In this repo's Settings, Secrets and variables, Actions:
   - secret `ASC_KEY_ID`: the Key ID
   - secret `ASC_ISSUER_ID`: the Issuer ID
   - secret `ASC_KEY_P8`: the whole text of the .p8 file, including the BEGIN and END lines
   - variable `APPLE_TEAM_ID`: the Team ID (developer.apple.com, Membership details). (Done 11/3/2026.)
5. Run the workflow. Then App Store Connect, the app, TestFlight, Internal Testing, a group with yourself in it; install
   TestFlight on the iPhone and accept the invite. Internal testers (up to 100 people on the team) need no review; builds expire
   after 90 days.

If the export step ever fails for want of a signing certificate, the fallback is a distribution certificate made by hand and kept
as two more secrets (the .p12 and its password); the workflow would import it before the export.
